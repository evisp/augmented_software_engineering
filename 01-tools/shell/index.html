    Shell Basics¶

    50 min Tools Needs: Ubuntu in WSL, or a Mac or Linux terminal

    The shell is the program that reads what you type in the terminal and makes it happen. In this tutorial you learn what it is, how to move around the filesystem with it, and how to find answers on your own.

    Why this matters¶

    Servers have no mouse. When you deploy code, debug a container or fix something on a remote machine, the shell is all you get. Holberton's Checker also runs everything from a shell, so the faster you are here, the faster every project goes.

    It is also simpler than it looks. A dozen commands cover most of what you will do in a day.

    Terminal, shell and prompt¶

    People use terminal and shell as if they mean the same thing. They do not.

    • The terminal is the window. It draws text and passes your keys along. Windows Terminal and the VS Code panel are both terminals.
    • The shell is the program inside it that reads a command, works out what you meant and runs it. On Ubuntu the default shell is bash. You can check yours with echo $SHELL.
    • The prompt is the text the shell prints when it is ready for your next command.
    yourname@LAPTOP:~/holberton$
    Part Meaning
    yourname the user you are logged in as
    LAPTOP the name of the machine
    ~/holberton your current folder, the working directory
    $ you are a normal user. It becomes # when you are root

    RTFM: read the manual¶

    RTFM stands for "read the fine manual", and it is the first advice any experienced developer gives. Almost every command ships with its own documentation, written by the people who built it.

    man ls

    This opens the manual page for ls. Inside it:

    Key What it does
    Space / B Page down / page up
    / then a word Search. N jumps to the next match
    Q Quit

    Some commands are not separate programs but are built into the shell itself, such as cd. Those use help:

    type cd        # cd is a shell builtin
help cd
type ls        # ls is /usr/bin/ls

    For a quick summary of any program, try ls --help.

    AI in the loop

    An assistant is a fast way to understand a command: ask "what does ls -la do, flag by flag?". But assistants sometimes invent flags that do not exist. Treat the answer as a lead, then confirm it with man. The manual describes the version actually installed on your machine.

    The filesystem is a tree¶

    Linux keeps every file in a single tree. There are no drive letters. The top of the tree is the root directory, written /.

    Three places on that tree matter most:

    • / is the root directory, the top of everything.
    • /home/you is your home directory, written ~ for short. Your files and settings live here.
    • /root is the home directory of the user called root, the administrator account. It is just one folder inside /, not the top of the tree. The names are confusing; the picture is not.

    Every file has a path that says where it sits in the tree:

    • An absolute path starts at the root: /home/you/holberton.
    • A relative path starts from where you are now: holberton, or ../tmp.

    Move around¶

    You are always in one directory, called the working directory. Three commands are enough to move around.

    Where am I? pwd prints the working directory.

    pwd

    /home/you

    What is here? ls lists the contents.

    ls            # names only
ls -l         # long format: permissions, owner, size, date
ls -la        # long format, including hidden files
ls /etc       # list another directory without going there

    Go somewhere. cd changes the working directory.

    cd holberton          # relative: into holberton, below where you are
cd /tmp               # absolute: straight to /tmp
cd ..                 # up one level
cd                    # home, from anywhere (same as cd ~)
cd -                  # back to the previous directory, and print it

    cd - is the one people forget. It flips between your last two locations, which is handy when you are working in two folders at once.

    ., .. and hidden files¶

    Run ls -la in your home folder:

    drwxr-x--- 5 you you 4096 Oct 20 09:12 .
drwxr-xr-x 3 root root 4096 Oct 19 18:40 ..
-rw-r--r-- 1 you you  220 Oct 19 18:40 .bash_logout
-rw-r--r-- 1 you you 3771 Oct 19 18:40 .bashrc
drwxr-xr-x 2 you you 4096 Oct 20 09:12 holberton
    • . is the directory you are in. ./script.sh means "the script.sh in this folder".
    • .. is the directory above it. cd .. goes up one level.
    • Hidden files are any files whose name starts with a dot, such as .bashrc. Plain ls skips them; ls -a shows them. They usually hold settings, which is why they are kept out of the way.

    There is nothing secret about a hidden file. The dot only changes whether ls shows it by default.

    Use the history¶

    The shell remembers what you typed.

    Do this What happens
    Up / Down Walk back and forward through previous commands
    history List recent commands, numbered
    !42 Run command number 42 from that list again
    !! Run the last command again. sudo !! reruns it as root
    Ctrl+R then type Search backwards for a command containing that text

    Ctrl+R saves more time than anything else on this page. Try it now: press it, type cd, and press Ctrl+R again to see older matches.

    Write your first script¶

    A shell script is a text file of commands that run one after the other. The first line is the shebang: #! followed by the path to the program that should run the file.

    hello_shell
    #!/bin/bash
echo "Hello from the shell"

    The shebang tells Linux to run this file with /bin/bash. Without it, Linux has to guess, and Holberton's checkers will reject the file.

    Create it, make it executable, and run it:

    cd ~/holberton
code hello_shell        # write the two lines and save
chmod u+x hello_shell
./hello_shell

    chmod u+x gives you, the owner, permission to execute the file. You learn exactly how that works in Shell Permissions. The ./ says "the file in this folder", because the shell does not look in the current folder for programs unless you tell it to.

    Holberton script conventions

    Projects usually ask for the shebang #!/bin/bash on the first line, a final newline at the end of the file, and nothing else on the first line. The VS Code settings from the VS Code tutorial add the final newline for you.

    When something goes wrong¶

    Permission denied when running a script

    The file is not executable. Run chmod u+x filename, then try ./filename again.

    command not found

    Check the spelling first. If you are running your own script, add ./ in front of the name. If it is a program, it may not be installed: sudo apt install name usually fixes it.

    No such file or directory

    The path is wrong relative to where you are. Run pwd to see where you are and ls to see what is actually there. Remember that names are case sensitive: Holberton and holberton are different.

    I am stuck inside a manual page

    Press Q. The same works for less and most other full-screen viewers.

    Quick reference¶

    Command What it does
    pwd Print the working directory
    ls -la List everything here, hidden files included, in long format
    cd path Change to path
    cd or cd ~ Go to your home directory
    cd .. / cd - Up one level / back to the previous directory
    man command Read the manual for a command
    help builtin Read the help for a shell builtin such as cd
    type command Say whether a command is a builtin or a program
    history List recent commands
    echo $SHELL Show which shell you are using
