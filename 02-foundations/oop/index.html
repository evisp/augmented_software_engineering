    Object-Oriented Design¶

    Model problems with classes: bundle data with the rules that protect it, build families of related types, and describe your design with UML and design patterns. Five projects, one running example.

    Foundations 40 h 5 projects Needs: Python Fundamentals

    Tutorials published3 of 5

    One example, five projects¶

    Every tutorial in this module builds on the same small digital wallet. You start with a single Account class and finish with a family of account types, a design you can draw in UML, and the patterns that keep it easy to change.

    Companion repository

    The code for each stage is in evisp/oop-wallet, saved under a Git tag per tutorial: v1-classes, v2-inheritance, and so on. Write each version yourself first, then compare it with the tag.

    AI in the loop

    Object-oriented code is where assistants are most tempting: ask for a class and you get fifty tidy lines. Write your own design first, from the description in each tutorial, then ask an assistant to review it: what could put the object into an invalid state, which names are unclear, what would be hard to change. You learn design by making the decisions, not by reading someone else's.
