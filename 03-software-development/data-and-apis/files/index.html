    File Handling¶

    75 min Data & APIs Needs: Exception Handling

    Every program you have written so far forgets everything the moment it stops. A file is the simplest way to keep data: write it once, read it back tomorrow. In this tutorial you open, write, read and close text files, and save structured data as JSON, all on a small library's book list.

    Why this matters¶

    Almost every program touches files: settings, logs, exports, data someone else produced. And JSON is how programs pass data to each other: the configuration of a tool, the answer from a web API, the body of a request. Once you can read and write it, a whole world of data opens up.

    Before you start¶

    You need Python 3 in your WSL terminal and VS Code, as set up in Environment & First Programs. Create a practice folder and download the two files this tutorial uses:

    mkdir -p ~/library && cd ~/library

curl -O https://evisp.github.io/augmented_software_engineering/assets/files/catalog.json

    Step 1: Files and paths¶

    A file is a named piece of data on disk. A text file, like books.txt, holds characters. On disk, each character is stored as one or more bytes, and the rule that maps characters to bytes is the encoding. The modern standard is UTF-8, which can store any character: ë, é, ç, Chinese, emoji.

    To open a file, Python needs its path, the directions to it:

    • An absolute path starts at the root, /, and works from anywhere.
    • A relative path, like books.txt, is looked up from the current working directory: the folder your terminal is in when you run python3. Not the folder the script is in.

    Python tells you the current working directory:

    where.py
    import os

print(os.getcwd())

    python3 where.py

    /home/ada/library

    These examples run as a user called ada; your folder will show your own user name.

    Try it

    From ~/library, run cd .. and then python3 library/where.py. What does it print, and would open("books.txt") still work?

    Answer

    It prints /home/ada, the folder the terminal is in, even though the script is in library. A relative books.txt would now be looked up in /home/ada, and fail with FileNotFoundError. Run your scripts from the folder that holds the files.

    Step 2: Open and close a file¶

    open() connects your program to a file and returns a file object. You read and write through that object, then close it:

    first_open.py
    file = open("books.txt", "r", encoding="utf-8")
print(file)
print(file.read(25))
file.close()
print(file.closed)

    <_io.TextIOWrapper name='books.txt' mode='r' encoding='utf-8'>
Kronikë në gur;Ismail Kad
True

    open() takes three things:

    • the path, here "books.txt";
    • the mode, "r" for read. It is the default, so you can leave it out, as later examples do;
    • the encoding, here "utf-8".

    file.read(25) read the first 25 characters, and after close(), file.closed is True.

    Always pass encoding="utf-8". Without it, Python uses your system's default, which differs between computers. With the wrong encoding, books.txt cannot even be read, because of the ë in the very first title:

    wrong_encoding.py
    file = open("books.txt", encoding="ascii")
print(file.read())
file.close()

    UnicodeDecodeError: 'ascii' codec can't decode byte 0xc3 in position 6: ordinal not in range(128)

    Step 3: Choose a mode¶

    The mode decides what open() does to the file, and it matters most when the file already exists:

    Mode Meaning File exists File missing
    "r" read reads from the start FileNotFoundError
    "w" write empties it first, then writes creates it
    "a" append keeps it, writes at the end creates it
    "x" create FileExistsError creates it

    The red bar in the diagram is the cursor: the position where the next read or write happens. Step 7 is about it.

    "w" empties the file when it opens, not when it writes

    Opening a file with "w" deletes its content immediately, even if you never write anything:

    w_empties.py
    file = open("scratch.txt", "w", encoding="utf-8")
file.write("first version\n")
file.close()

file = open("scratch.txt", "w", encoding="utf-8")
file.close()

file = open("scratch.txt", encoding="utf-8")
print(repr(file.read()))
file.close()

    ''

    When you want to add to a file, use "a". When you must not overwrite an existing file, use "x", which refuses.

    Step 4: Write text¶

    write() writes a string and returns how many characters it wrote. It does not start a new line: you add "\n", the newline character, yourself.

    write_list.py
    file = open("reading-list.txt", "w", encoding="utf-8")
file.write("Dune\n")
file.write("The Hobbit\n")
count = file.write("Kronikë në gur\n")
file.close()
print(count)

    15

    Kronikë në gur is 14 characters, plus the newline: 15. Look at the result from the terminal:

    cat reading-list.txt

    Dune
The Hobbit
Kronikë në gur

    Now add a book with mode "a":

    append_list.py
    file = open("reading-list.txt", "a", encoding="utf-8")
file.write("Don Quixote\n")
file.close()

    Run it twice, then look again:

    Dune
The Hobbit
Kronikë në gur
Don Quixote
Don Quixote

    Append never removes anything: each run adds one more line. That is what you want for a log, and a surprise if you expected a single copy.

    Forget the "\n", and the lines run together:

    no_newline.py
    file = open("squashed.txt", "w", encoding="utf-8")
file.write("Dune")
file.write("The Hobbit")
file.close()

    DuneThe Hobbit

    print() can also write to a file, with file=. It adds the newline for you:

    print_file.py
    file = open("shortlist.txt", "w", encoding="utf-8")
print("Dune", file=file)
print("The Hobbit", file=file)
file.close()

    Step 5: Read a file¶

    Python gives you four ways to read text:

    Call Returns
    file.read() the whole file, as one string
    file.readline() the next line, as a string, "\n" included
    file.readlines() all the lines, as a list of strings
    for line in file: one line at a time, in a loop

    Every line you read ends with the newline character, "\n". repr() shows it:

    read_line.py
    file = open("books.txt", encoding="utf-8")
first = file.readline()
print(repr(first))
file.close()

    'Kronikë në gur;Ismail Kadare;1971\n'

    That is why you usually remove it with rstrip("\n") before using the line. Then split(";") cuts the line into its three parts. Every book from before 1900:

    old_books.py
    file = open("books.txt", encoding="utf-8")
for line in file:
    title, author, year = line.rstrip("\n").split(";")
    if int(year) < 1900:
        print(f"{title} ({year}), {author}")
file.close()

    Pride and Prejudice (1813), Jane Austen
Don Quixote (1605), Miguel de Cervantes

    readlines() and read() load the whole file at once, which is fine for small files:

    read_all.py
    file = open("books.txt", encoding="utf-8")
lines = file.readlines()
file.close()
print(len(lines))
print(repr(lines[-1]))

file = open("books.txt", encoding="utf-8")
text = file.read()
file.close()
print(text.count("Kadare"))

    10
'One Hundred Years of Solitude;Gabriel García Márquez;1967\n'
2

    The loop, for line in file:, reads one line at a time and never holds the whole file in memory. Prefer it: it works the same on a file of ten lines and on one of ten million.

    Try it

    Find the oldest book in books.txt and print its title and year.

    Answer
    oldest.py
    oldest_title = None
oldest_year = None

file = open("books.txt", encoding="utf-8")
for line in file:
    title, author, year = line.rstrip("\n").split(";")
    if oldest_year is None or int(year) < oldest_year:
        oldest_title, oldest_year = title, int(year)
file.close()

print(f"Oldest: {oldest_title} ({oldest_year})")

    Oldest: Don Quixote (1605)

    Step 6: Close files with with¶

    Closing a file is not a formality. Python buffers what you write: it collects it in memory and saves it to disk in batches, and the last batch is only saved when the file is closed. Until then, other programs, or even your own, may see nothing:

    buffer_demo.py
    writer = open("buffer-demo.txt", "w", encoding="utf-8")
writer.write("not saved yet\n")

reader = open("buffer-demo.txt", encoding="utf-8")
print(repr(reader.read()))

writer.close()
print(repr(reader.read()))
reader.close()

    ''
'not saved yet\n'

    The second open() read an empty file. Only after writer.close() was the text really on disk.

    The danger is an error between open() and close(): the close() never runs. The with statement solves it. It closes the file when the block ends, whatever happens inside:

    with_read.py
    with open("reading-list.txt", encoding="utf-8") as file:
    print(file.read(), end="")

print(file.closed)

    Dune
The Hobbit
Kronikë në gur
Don Quixote
Don Quixote
True

    Even when an exception interrupts the block, the file is closed:

    with_error.py
    try:
    with open("reading-list.txt", encoding="utf-8") as file:
        for line in file:
            year = int(line)
except ValueError as error:
    print("Error:", error)

print(file.closed)

    Error: invalid literal for int() with base 10: 'Dune\n'
True

    From here on, every example uses with. One with can open several files. This one copies just the titles from books.txt into a new file:

    titles_only.py
    with open("books.txt", encoding="utf-8") as source, \
        open("titles.txt", "w", encoding="utf-8") as target:
    for line in source:
        title = line.split(";")[0]
        target.write(title + "\n")

    head -n 4 titles.txt

    Kronikë në gur
Gjenerali i ushtrisë së vdekur
The Little Prince
Nineteen Eighty-Four

    Step 7: Move the cursor¶

    An open file remembers a cursor: the position of the next read or write. Each read moves it forward. tell() reports where it is, and seek() moves it.

    cursor.py
    with open("reading-list.txt", encoding="utf-8") as file:
    print(file.tell())
    print(repr(file.readline()))
    print(file.tell())
    print(repr(file.read()))
    print(repr(file.read()))
    file.seek(0)
    print(repr(file.readline()))

    0
'Dune\n'
5
'The Hobbit\nKronikë në gur\nDon Quixote\nDon Quixote\n'
''
'Dune\n'

    Notice the last read() returned '': the cursor was already at the end, so there was nothing left. That is the classic "my second read is empty" bug. seek(0) goes back to the start.

    Positions in text files

    In a text file, tell() counts bytes, not characters, and ë takes two bytes in UTF-8. So with text files, only seek() to 0 or to a number that tell() gave you earlier.

    Try it

    In a single with block, count the lines of books.txt, then go back and read the first line again.

    Answer
    twice.py
    with open("books.txt", encoding="utf-8") as file:
    count = len(file.readlines())
    file.seek(0)
    first = file.readline().rstrip("\n")

print(count, "books")
print("First:", first)

    10 books
First: Kronikë në gur;Ismail Kadare;1971

    Step 8: Handle missing files¶

    Opening a file can fail, and the error says why:

    Exception Cause
    FileNotFoundError No file at that path, in mode "r"
    PermissionError The file's permissions do not allow it
    IsADirectoryError The path is a folder, not a file
    FileExistsError The file exists, in mode "x"

    Catch the one you expect with try and except, as in Exception Handling. A missing list is often just an empty list:

    missing.py
    def read_titles(path):
    """Return the lines of a list file, or an empty list if it is missing."""
    try:
        with open(path, encoding="utf-8") as file:
            return [line.rstrip("\n") for line in file]
    except FileNotFoundError:
        print(f"No file called {path}, starting with an empty list")
        return []


print(read_titles("reading-list.txt"))
print(read_titles("favourites.txt"))

    ['Dune', 'The Hobbit', 'Kronikë në gur', 'Don Quixote', 'Don Quixote']
No file called favourites.txt, starting with an empty list
[]

    And a file with no read permission:

    echo "secret" > locked.txt
chmod 000 locked.txt
python3 -c 'open("locked.txt", encoding="utf-8")'

    PermissionError: [Errno 13] Permission denied: 'locked.txt'

    Try it

    What happens with open("~/library/books.txt", encoding="utf-8")? The file is right there.

    Answer
    tilde.py
    file = open("~/library/books.txt", encoding="utf-8")

    FileNotFoundError: [Errno 2] No such file or directory: '~/library/books.txt'

    ~ is a shortcut that the shell understands, not Python. Python looks for a folder literally called ~. Expand it first:

    tilde_fix.py
    import os

path = os.path.expanduser("~/library/books.txt")
print(path)
with open(path, encoding="utf-8") as file:
    print(file.readline(), end="")

    /home/ada/library/books.txt
Kronikë në gur;Ismail Kadare;1971

    Step 9: Save data as JSON¶

    Lines of text suit a simple list. But a catalog has structure: each book has a title, a year that is a number, a yes-or-no available, and a list of tags. For that, use JSON, a text format for data. Here is the start of catalog.json:

    catalog.json
    [
  {
    "title": "Kronikë në gur",
    "author": "Ismail Kadare",
    "year": 1971,
    "available": true,
    "tags": ["albanian", "novel"]
  },
  {
    "title": "The Little Prince",
    "author": "Antoine de Saint-Exupéry",
    "year": 1943,
    "available": false,
    "tags": ["classic", "children"]
  },
  ...

    JSON looks like Python, with a few differences:

    Python JSON
    dict object {...}, keys always strings in double quotes
    list, tuple array [...]
    str string, in double quotes
    int, float number
    True, False true, false
    None null

    Turning data into text like this is called serialisation; turning the text back into data is deserialisation. The json module does both, with four functions:

    The s stands for string: dumps and loads work with strings, dump and load work with files.

    json_text.py
    import json

book = {
    "title": "Dune",
    "author": "Frank Herbert",
    "year": 1965,
    "available": True,
    "tags": ["sci-fi"],
    "borrower": None,
}

text = json.dumps(book)
print(text)
print(type(text).__name__)

back = json.loads(text)
print(back == book)

    {"title": "Dune", "author": "Frank Herbert", "year": 1965, "available": true, "tags": ["sci-fi"], "borrower": null}
str
True

    Notice the changes in the text: True became true, None became null, and everything is in double quotes. loads turned it back into an equal dictionary.

    Reading a JSON file gives you ordinary Python lists and dictionaries:

    load_catalog.py
    import json

with open("catalog.json", encoding="utf-8") as file:
    catalog = json.load(file)

print(type(catalog).__name__, len(catalog))
print(catalog[0]["title"], catalog[0]["tags"])

for book in catalog:
    if book["available"]:
        print("-", book["title"])

    list 6
Kronikë në gur ['albanian', 'novel']
- Kronikë në gur
- Nineteen Eighty-Four
- Pride and Prejudice
- The Hobbit

    To save, change the data and dump it back. indent=2 makes the file readable for people, and ensure_ascii=False keeps letters such as ë as they are:

    save_catalog.py
    import json

with open("catalog.json", encoding="utf-8") as file:
    catalog = json.load(file)

catalog.append({
    "title": "Things Fall Apart",
    "author": "Chinua Achebe",
    "year": 1958,
    "available": True,
    "tags": ["classic", "novel"],
})

with open("catalog.json", "w", encoding="utf-8") as file:
    json.dump(catalog, file, indent=2, ensure_ascii=False)

print(len(catalog), "books saved")

    7 books saved

    tail -n 9 catalog.json

        "author": "Chinua Achebe",
    "year": 1958,
    "available": true,
    "tags": [
      "classic",
      "novel"
    ]
  }
]

    Without ensure_ascii=False, JSON escapes every non-English letter. Still valid, but hard to read:

    ascii.py
    import json

print(json.dumps("Kronikë në gur"))
print(json.dumps("Kronikë në gur", ensure_ascii=False))

    "Kronik\u00eb n\u00eb gur"
"Kronikë në gur"

    JSON cannot store everything Python can. Keys become strings, tuples come back as lists, sets are refused, and text that is not valid JSON cannot be loaded:

    json_limits.py
    import json

print(json.loads(json.dumps({1: "one"})))
print(json.loads(json.dumps(("Dune", 1965))))

try:
    json.dumps({"Dune", "The Hobbit"})
except TypeError as error:
    print("TypeError:", error)

try:
    json.loads("{'title': 'Dune'}")
except json.JSONDecodeError as error:
    print("JSONDecodeError:", error)

    {'1': 'one'}
['Dune', 1965]
TypeError: Object of type set is not JSON serializable
JSONDecodeError: Expecting property name enclosed in double quotes: line 1 column 2 (char 1)

    The last one is the most common JSON mistake: single quotes are not JSON.

    Try it

    Load catalog.json and list the titles of the books tagged "classic".

    Answer
    count_tag.py
    import json

    catalog = json.load(file)

    4 ['The Little Prince', 'Nineteen Eighty-Four', 'Pride and Prejudice', 'Things Fall Apart']

    Step 10: Save objects as JSON¶

    In Object-Oriented Design you modelled data with classes. A library would have a Book class. But json only knows dictionaries, lists, strings, numbers, booleans and None. An object of your own class is refused:

    not_serializable.py
    import json


class Book:
    """A book in the library catalog."""

    def __init__(self, title, year):
        self.title = title
        self.year = year


dune = Book("Dune", 1965)
try:
    json.dumps(dune)
except TypeError as error:
    print("TypeError:", error)

    TypeError: Object of type Book is not JSON serializable

    The usual solution: give the class two methods that translate between an object and a dictionary. to_dict() turns the object into a dictionary that json can save, and the class method from_dict() builds an object back from a loaded dictionary. Then two small functions save and load a whole list of books:

    book.py
    """A Book class that can be saved to and loaded from JSON."""
import json


class Book:
    """A book in the library catalog."""

    def __init__(self, title, author, year, available=True):
        self.title = title
        self.author = author
        self.year = year
        self.available = available

    def __repr__(self):
        state = "in" if self.available else "out"
        return f"Book({self.title!r}, {self.year}, {state})"

    def to_dict(self):
        """Return the book as a dictionary that json can save."""
        return {
            "title": self.title,
            "author": self.author,
            "year": self.year,
            "available": self.available,
        }

    @classmethod
    def from_dict(cls, data):
        """Build a book from a dictionary loaded from JSON."""
        return cls(data["title"], data["author"], data["year"],
                   data["available"])


def save_books(path, books):
    """Save a list of books to a JSON file."""
    with open(path, "w", encoding="utf-8") as file:
        json.dump([book.to_dict() for book in books], file,
                  indent=2, ensure_ascii=False)


def load_books(path):
    """Load a list of books from a JSON file."""
    with open(path, encoding="utf-8") as file:
        return [Book.from_dict(data) for data in json.load(file)]

    from_dict reads only the keys it needs, so it can even load the books in catalog.json, which have extra tags:

    shelf.py
    from book import load_books, save_books

shelf = load_books("catalog.json")
print(shelf[:3])

shelf[0].available = False
save_books("shelf.json", shelf)

again = load_books("shelf.json")
print(again[0])
print(again[0] is shelf[0], again[0].title == shelf[0].title)

    [Book('Kronikë në gur', 1971, in), Book('The Little Prince', 1943, out), Book('Nineteen Eighty-Four', 1949, in)]
Book('Kronikë në gur', 1971, out)
False True

    head -n 8 shelf.json

    [
  {
    "title": "Kronikë në gur",
    "author": "Ismail Kadare",
    "year": 1971,
    "available": false
  },
  {

    The loaded book is a new object with the same data: is is False, but the titles match. That is what deserialisation means: you get the data back, not the same object.

    What about vars()?

    For a simple object, vars(book), or book.__dict__, already gives a dictionary of its attributes:

    vars_demo.py
    from book import Book

dune = Book("Dune", "Frank Herbert", 1965)
print(vars(dune))

    {'title': 'Dune', 'author': 'Frank Herbert', 'year': 1965, 'available': True}

    It is a handy shortcut. An explicit to_dict() is safer: you choose exactly what goes into the file, and renaming an attribute later does not silently change your file format.

    Try it

    Add a borrower attribute to Book, None by default, and save it in to_dict(). Make sure from_dict() can still load shelf.json, which was saved before borrower existed.

    Answer
    book_borrower.py
    """Book with a borrower: still loads files saved before the change."""
import json


class Book:
    """A book in the library catalog."""

    def __init__(self, title, author, year, available=True, borrower=None):
        self.title = title
        self.author = author
        self.year = year
        self.available = available
        self.borrower = borrower

    def to_dict(self):
        """Return the book as a dictionary that json can save."""
        return {
            "title": self.title,
            "author": self.author,
            "year": self.year,
            "available": self.available,
            "borrower": self.borrower,
        }

    @classmethod
    def from_dict(cls, data):
        """Build a book from a dictionary loaded from JSON."""
        return cls(data["title"], data["author"], data["year"],
                   data["available"], data.get("borrower"))


with open("shelf.json", encoding="utf-8") as file:
    shelf = [Book.from_dict(data) for data in json.load(file)]

print(shelf[0].title, shelf[0].borrower)
shelf[0].borrower = "Ada"
print(json.dumps(shelf[0].to_dict(), ensure_ascii=False))

    Kronikë në gur None
{"title": "Kronikë në gur", "author": "Ismail Kadare", "year": 1971, "available": false, "borrower": "Ada"}

    data.get("borrower") returns None when the key is missing, where data["borrower"] would raise KeyError. Old files keep loading.

    AI in the loop

    Assistants write file code in seconds, and one wrong letter in a mode destroys data: a "w" where you meant "a" empties the file without a word. Before you run file code you did not write, find every open() and say out loud which file it touches and in which mode. Try it on a copy of your data first.

    When something goes wrong¶

    FileNotFoundError, but the file is right there

    The path is relative and the terminal is in another folder. Run pwd and ls; cd to the folder with the file, or use an absolute path. Also check for ~ in the path (see Step 8) and for typos in the extension: book.txt is not books.txt.

    UnicodeDecodeError

    The file was opened without encoding="utf-8", or with the wrong encoding. Add encoding="utf-8" to every open().

    My file is empty after the script ran

    It was opened with "w", which empties the file as it opens. To add to a file, use "a".

    Every line prints with an empty line after it

    Each line ends with "\n", and print() adds another. Use line.rstrip("\n"), or print(line, end="").

    The second read returns nothing

    The cursor is at the end of the file. seek(0) goes back to the start, or read the file once into a variable and reuse it.

    json.decoder.JSONDecodeError

    The text is not valid JSON. The usual causes are single quotes, a comma after the last item, or an empty file. The message gives the line and column of the problem.

    TypeError: Object of type ... is not JSON serializable

    You passed something json does not know: a set, or an object of your own class. Convert it first: list(the_set), or the_object.to_dict().

    6. Safe loading. Write load_or_empty(path), which returns the data in a JSON file, or [] if the file is missing or is not valid JSON, with a warning in that second case. Test it on an empty file.

    Answer
    p6_safe_load.py
    import json


def load_or_empty(path):
    """Return the data in a JSON file, or [] if it is missing or broken."""
    try:
        with open(path, encoding="utf-8") as file:
            return json.load(file)
    except FileNotFoundError:
        return []
    except json.JSONDecodeError as error:
        print(f"Warning: {path} is not valid JSON ({error})")
        return []


open("empty.json", "w", encoding="utf-8").close()

print(load_or_empty("nothing-here.json"))
print(load_or_empty("empty.json"))

    7. Borrow a book. Write borrow(path, title), which loads the catalog, marks the book as not available, and saves the file. It should refuse a book that is already borrowed, or that does not exist.

    Answer
    p7_borrow.py
    import json


def borrow(path, title):
    """Mark a book in a catalog file as borrowed, and save the file."""
    with open(path, encoding="utf-8") as file:
        catalog = json.load(file)

    for book in catalog:
        if book["title"] == title:
            if not book["available"]:
                print(f"{title} is already borrowed")
                return False
            book["available"] = False
            with open(path, "w", encoding="utf-8") as file:
                json.dump(catalog, file, indent=2, ensure_ascii=False)
            print(f"{title} borrowed")
            return True

    print(f"No book called {title}")
    return False


borrow("catalog.json", "The Hobbit")
borrow("catalog.json", "The Hobbit")
borrow("catalog.json", "Ulysses")

    Quick reference¶

    Code What it does
    open(path, mode, encoding="utf-8") Open a file; mode "r", "w", "a" or "x"
    with open(...) as file: Open, and close automatically when the block ends
    file.write(text) Write text; add "\n" yourself
    print(text, file=file) Write text and a newline
    file.read() The whole file as one string
    file.readline() / file.readlines() One line / all lines as a list
    for line in file: Line by line
    line.rstrip("\n") Remove the newline at the end
    file.tell() / file.seek(0) Where the cursor is / back to the start
    os.getcwd() The current working directory
    json.dumps(data) / json.loads(text) Data to a JSON string / back
    json.dump(data, file, indent=2, ensure_ascii=False) Save data to a JSON file
    json.load(file) Load data from a JSON file
    obj.to_dict() / Cls.from_dict(data) Your own class to JSON-ready data / back
