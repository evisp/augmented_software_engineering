    SQL: CRUD Operations¶

    90 min Data & APIs Needs: File Handling

    Files are good for a list or a settings file. When you need to find, sort, count and change many records, you need a database. In this tutorial you meet the relational model and learn the language every relational database speaks, SQL: you create a table, then read, filter, sort, add, change, delete and summarise the library's books.

    Why this matters¶

    Nearly every application keeps its data in a relational database: user accounts, orders, bookings, messages. SQL has been the way to talk to those databases for fifty years, and the SQL you learn here works, almost unchanged, in SQLite, PostgreSQL, MySQL and SQL Server.

    It is also the skill that answers questions. "How many books does each author have?" needs a loop and a dictionary in Python. In SQL it is three short lines.

    Before you start¶

    We use SQLite: a whole database in one file, with no server to install. Install its command-line tool in your WSL terminal:

    sudo apt update && sudo apt install -y sqlite3
sqlite3 --version

    Then download the practice data and load it into a new database file, books.db:

    mkdir -p ~/library && cd ~/library
curl -O https://evisp.github.io/augmented_software_engineering/assets/sql/books.sql
sqlite3 books.db < books.sql

    You can also download books.sql from the browser. It creates a table of 20 books. Loading it again resets the table, so if you break something, run the last command again.

    Step 1: Tables, rows and columns¶

    A relational database stores data in tables. A table looks like a spreadsheet, but it is stricter, and that strictness is what makes it reliable.

    • A table holds one kind of thing: the books table holds books, one per row.
    • A column has a name and a type, and every value in it is the same kind of fact: year is always a whole number, title always text.
    • A row is one record: one book, with a value for each column.
    • The primary key, here id, has a different value in every row, so each row can be found and changed on its own.
    • NULL means "no value": unknown or missing. It is not zero and not an empty string, and it needs special care, as you will see.

    The order of rows in a table means nothing. A database returns rows in whatever order is fastest, unless you ask for an order.

    Step 2: Open the database¶

    Open books.db in the SQLite shell:

    sqlite3 books.db

    The prompt changes to sqlite>. Everything you type there is either SQL, which ends with a semicolon ;, or a shell command, which starts with a dot. Make the results readable first:

    sqlite> .headers on
sqlite> .mode box

    Every output on this page uses those two settings. To have them every time, put both lines in a file called ~/.sqliterc. Now look around. .tables lists the tables:

    .tables

    books

    .schema shows how a table was created:

    .schema books

    CREATE TABLE books (
    id        INTEGER PRIMARY KEY,
    title     TEXT    NOT NULL,
    author    TEXT    NOT NULL,
    year      INTEGER,
    genre     TEXT,
    pages     INTEGER,
    available INTEGER NOT NULL DEFAULT 1
);

    Leave the shell with .quit or Ctrl+D. You can also run a file of SQL without opening the shell: sqlite3 books.db < some-file.sql, which is exactly how you loaded the practice data.

    Step 3: Create a table¶

    That schema is a CREATE TABLE statement. Read it line by line:

    • INTEGER PRIMARY KEY makes id the primary key. Leave it out when you add a row, and SQLite fills in the next number.
    • TEXT and INTEGER are the types. SQLite also has REAL for decimals and BLOB for raw bytes. There is no true/false type: available uses 1 for yes and 0 for no.
    • NOT NULL means the column must always have a value. genre and pages have no such rule, so they may be NULL.
    • DEFAULT 1 fills in a value when a new row does not give one.

    books.sql also starts with DROP TABLE IF EXISTS books;, which deletes the whole table, data and all. That is what makes reloading the file a reset.

    Dates have no special type in SQLite either. Store them as text in the form YYYY-MM-DD: in that form they sort and compare correctly.

    Try it

    The library also needs its members. Create a table members with an id primary key, a name that is required, an email that is required and must be different for every member, and a joined_on date that defaults to today. Check it with .tables.

    Answer

    UNIQUE refuses a value that is already in the column, and CURRENT_DATE is today's date:

    CREATE TABLE members (
    id        INTEGER PRIMARY KEY,
    name      TEXT NOT NULL,
    email     TEXT NOT NULL UNIQUE,

    Step 5: Filter rows with WHERE¶

    WHERE keeps only the rows for which a condition is true. All of Kadare's books:

    SELECT id, title, year FROM books WHERE author = 'Ismail Kadare';

    ┌────┬────────────────────────────────┬──────┐
│ id │             title              │ year │
├────┼────────────────────────────────┼──────┤
│ 1  │ Kronikë në gur                 │ 1971 │
│ 2  │ Gjenerali i ushtrisë së vdekur │ 1963 │
│ 3  │ Prilli i thyer                 │ 1978 │
└────┴────────────────────────────────┴──────┘

    The conditions you will use most:

    Condition Example
    = <> < <= > >= year < 1900
    AND, OR, NOT genre = 'novel' AND pages > 300
    IN (...) genre IN ('satire', 'dystopia')
    BETWEEN a AND b year BETWEEN 1940 AND 1949, both ends included
    LIKE title LIKE 'The %': % is any text, _ one character
    IS NULL, IS NOT NULL genre IS NULL

    Books from before 1900:

    SELECT title, author, year FROM books WHERE year < 1900;

    Step 6: Sort and limit¶

    ORDER BY sorts the result, and DESC puts the largest first. Together with LIMIT, it answers "top N" questions. The three longest books:

    SELECT title, pages FROM books ORDER BY pages DESC LIMIT 3;

    ┌─────────────┬───────┐
│    title    │ pages │
├─────────────┼───────┤
│ Don Quixote │ 1072  │
│ Dune        │ 612   │
│ Emma        │ 474   │
└─────────────┴───────┘

    Sort by several columns, and the second one breaks ties in the first. Every novel, by author and then by year:

    SELECT author, year, title FROM books
WHERE genre = 'novel'
ORDER BY author, year;

    ┌────────────────────────┬──────┬────────────────────────────────┐
│         author         │ year │             title              │
├────────────────────────┼──────┼────────────────────────────────┤
│ Chinua Achebe          │ 1958 │ Things Fall Apart              │
│ Fatos Kongoli          │ 1992 │ I humburi                      │
│ Gabriel García Márquez │ 1967 │ One Hundred Years of Solitude  │
│ Ismail Kadare          │ 1963 │ Gjenerali i ushtrisë së vdekur │
│ Ismail Kadare          │ 1971 │ Kronikë në gur                 │
│ Ismail Kadare          │ 1978 │ Prilli i thyer                 │
│ Miguel de Cervantes    │ 1605 │ Don Quixote                    │
└────────────────────────┴──────┴────────────────────────────────┘

    OFFSET skips rows, which is how a website shows page 2 of a list:

    SELECT id, title FROM books ORDER BY id LIMIT 5 OFFSET 5;

    ┌────┬──────────────────────┐
│ id │        title         │
├────┼──────────────────────┤
│ 6  │ The Little Prince    │
│ 7  │ Nineteen Eighty-Four │
│ 8  │ Animal Farm          │
│ 9  │ Things Fall Apart    │
│ 10 │ Pride and Prejudice  │
└────┴──────────────────────┘

    Without ORDER BY, "the first five rows" means whichever five the database happens to return. Whenever the order matters, say so.

    Step 7: Add rows with INSERT¶

    INSERT INTO adds rows. Name the columns, then give the values in the same order. Leave out id, and SQLite assigns the next number; leave out available, and it gets its default, 1:

    INSERT INTO books (title, author, year, genre, pages)
VALUES ('The Left Hand of Darkness', 'Ursula K. Le Guin', 1969, 'sci-fi', 304);

    VALUES can take several rows at once, separated by commas, and NULL leaves a column empty:

    INSERT INTO books (title, author, year, genre, pages) VALUES
    ('Python Crash Course', 'Eric Matthes', 2019, 'programming', 544),
    ('Atomic Habits', 'James Clear', 2018, NULL, 320);

    Always check what you wrote:

    SELECT * FROM books WHERE id > 20;

    ┌────┬───────────────────────────┬───────────────────┬──────┬─────────────┬───────┬───────────┐
│ id │           title           │      author       │ year │    genre    │ pages │ available │
├────┼───────────────────────────┼───────────────────┼──────┼─────────────┼───────┼───────────┤
│ 21 │ The Left Hand of Darkness │ Ursula K. Le Guin │ 1969 │ sci-fi      │ 304   │ 1         │

    Step 8: Change and remove rows¶

    UPDATE changes values in the rows that match WHERE. Atomic Habits has no genre yet; give it one:

    UPDATE books SET genre = 'self-help' WHERE id = 23;

    One UPDATE can change several columns at once. The Left Hand of Darkness went out on loan, and its page count was wrong:

    UPDATE books SET available = 0, pages = 290 WHERE id = 21;

    SELECT id, title, genre, pages, available FROM books WHERE id > 20;

    ┌────┬───────────────────────────┬─────────────┬───────┬───────────┐
│ id │           title           │    genre    │ pages │ available │
├────┼───────────────────────────┼─────────────┼───────┼───────────┤
│ 21 │ The Left Hand of Darkness │ sci-fi      │ 290   │ 0         │
│ 22 │ Python Crash Course       │ programming │ 544   │ 1         │
│ 23 │ Atomic Habits             │ self-help   │ 320   │ 1         │
└────┴───────────────────────────┴─────────────┴───────┴───────────┘

    DELETE FROM removes the rows that match WHERE. Python Crash Course was added by mistake. Check the row first, then delete it:

    SELECT id, title FROM books WHERE id = 22;

    ┌────┬─────────────────────┐
│ id │        title        │
├────┼─────────────────────┤
│ 22 │ Python Crash Course │
└────┴─────────────────────┘

    DELETE FROM books WHERE id = 22;

    SELECT id, title FROM books WHERE id > 20;

    ┌────┬───────────────────────────┐
│ id │           title           │
├────┼───────────────────────────┤
│ 21 │ The Left Hand of Darkness │
│ 23 │ Atomic Habits             │
└────┴───────────────────────────┘

    Notice that each statement used the primary key to pick exactly one row. A condition such as WHERE author = 'Jane Austen' would change every one of her books.

    UPDATE and DELETE without WHERE change every row

    DELETE FROM books; empties the table, and UPDATE books SET available = 0; marks every book as out. There is no undo. Two habits protect you:

    1. Run the WHERE as a SELECT first, as above. If it shows exactly the rows you mean, the same WHERE is safe.
    2. Use a transaction for anything risky. BEGIN starts one; nothing is final until COMMIT, and ROLLBACK undoes it all. changes() reports how many rows the last statement touched:
    BEGIN;
UPDATE books SET available = 0;
SELECT changes() AS changed;
SELECT SUM(available) AS available FROM books;
ROLLBACK;
SELECT SUM(available) AS available FROM books;

    ┌─────────┐
│ changed │
├─────────┤
│ 22      │
└─────────┘
┌───────────┐
│ available │
├───────────┤
│ 0         │
└───────────┘
┌───────────┐
│ available │
├───────────┤
│ 16        │
└───────────┘

    The update touched all 22 rows and nothing was available, until ROLLBACK put everything back.

    These four statements, INSERT, SELECT, UPDATE and DELETE, are CRUD: create, read, update, delete. Almost everything an application does with its data is one of them.

    Step 9: Summarise with aggregate functions¶

    An aggregate function turns many rows into one value:

    Function Returns
    COUNT(*) the number of rows
    COUNT(column) the number of rows where that column is not NULL
    SUM(column) the total
    AVG(column) the average
    MIN(column), MAX(column) the smallest and largest value 
    SELECT COUNT(*) AS books, COUNT(genre) AS with_genre,
       COUNT(pages) AS with_pages, SUM(pages) AS total_pages
FROM books;

    ┌───────┬────────────┬────────────┬─────────────┐
│ books │ with_genre │ with_pages │ total_pages │
├───────┼────────────┼────────────┼─────────────┤
│ 22    │ 20         │ 20         │ 7171        │
└───────┴────────────┴────────────┴─────────────┘

    COUNT(*) counts every row, while COUNT(genre) skips the rows whose genre is NULL. AS gives a result column a readable name.

    Combine aggregates with WHERE to summarise only some rows. The shortest, longest and average novel:

    SELECT MIN(pages) AS shortest, MAX(pages) AS longest,
       ROUND(AVG(pages), 1) AS average
FROM books WHERE genre = 'novel';

    ┌──────────┬─────────┬─────────┐
│ shortest │ longest │ average │
├──────────┼─────────┼─────────┤
│ 192      │ 1072    │ 387.7   │
└──────────┴─────────┴─────────┘

    ROUND(..., 1) keeps one decimal place. Aggregates also skip NULLs: AVG(pages) averages only the books whose page count is known.

    Try it

    How many books are on the shelf, that is, available?

    Answer 
    SELECT COUNT(*) AS on_the_shelf FROM books WHERE available = 1;

    ┌──────────────┐
│ on_the_shelf │
├──────────────┤
│ 16           │
└──────────────┘

    SUM(available) gives the same answer, because available books hold 1.

    Step 10: Group rows with GROUP BY¶

    GROUP BY splits the rows into groups that share a value, and runs the aggregate once per group. The result has one row per group.

    How many books in each genre? The NULL genres form a group of their own, shown as an empty cell:

    SELECT genre, COUNT(*) AS books
FROM books
GROUP BY genre
ORDER BY books DESC, genre;

    ┌─────────────┬───────┐
│    genre    │ books │
├─────────────┼───────┤
│ novel       │ 7     │
│ programming │ 3     │
│             │ 2     │
│ romance     │ 2     │
│ satire      │ 2     │
│ sci-fi      │ 2     │
│ children    │ 1     │
│ dystopia    │ 1     │
│ fantasy     │ 1     │
│ self-help   │ 1     │
└─────────────┴───────┘

    To keep only some groups, use HAVING. WHERE filters rows before they are grouped; HAVING filters the groups after. The authors with more than one book:

    SELECT author, COUNT(*) AS books
FROM books
GROUP BY author
HAVING COUNT(*) > 1
ORDER BY books DESC, author;

    ┌───────────────┬───────┐
│    author     │ books │
├───────────────┼───────┤
│ Ismail Kadare │ 3     │
│ George Orwell │ 2     │
│ Jane Austen   │ 2     │
└───────────────┴───────┘

    Both can appear in one query. Genres whose books average more than 300 pages, leaving out the books with no genre:

    SELECT genre, COUNT(*) AS books, ROUND(AVG(pages)) AS avg_pages
FROM books
WHERE genre IS NOT NULL
GROUP BY genre
HAVING AVG(pages) > 300
ORDER BY avg_pages DESC;

    Step 11: Interpret results correctly¶

    A query that runs is not necessarily a query that answers your question. Most wrong results come from one fact: SQL does not run a query in the order you write it.

    Read it in that order, and the rules stop being arbitrary:

    • WHERE cannot use aggregates or column aliases: it runs before any groups or names exist. That is what HAVING is for.
    • ORDER BY can use aliases, such as ORDER BY books: it runs after SELECT has named them.
    • LIMIT applies last, to the sorted result. "Top three" only means something after an ORDER BY.

    A few more traps when reading results:

    • An aggregate over no rows is NULL, not zero. The page count of an author the library does not have prints as an empty cell:

      SELECT SUM(pages) AS total FROM books WHERE author = 'Nobody';

      ┌───────┐
│ total │
├───────┤
│       │
└───────┘

    • Whole numbers divide as whole numbers. Make one side a decimal to get a decimal answer:

      SELECT 7 / 2 AS whole, 7 / 2.0 AS decimal;

      ┌───────┬─────────┐
│ whole │ decimal │
├───────┼─────────┤
│ 3     │ 3.5     │
└───────┴─────────┘

    • Every column in a grouped SELECT must be grouped or aggregated. SQLite lets this query run, and shows one title from each genre, whichever it met first:

      SELECT genre, title FROM books GROUP BY genre;

      ┌─────────────┬───────────────────────────────────┐
│    genre    │               title               │
├─────────────┼───────────────────────────────────┤
│             │ Vargjet e lira                    │
│ children    │ The Little Prince                 │
│ dystopia    │ Nineteen Eighty-Four              │
│ fantasy     │ The Hobbit                        │
│ novel       │ Kronikë në gur                    │
│ programming │ Clean Code                        │
│ romance     │ Pride and Prejudice               │
│ satire      │ Shkëlqimi dhe rënia e shokut Zylo │
│ sci-fi      │ Dune                              │
│ self-help   │ Atomic Habits                     │
└─────────────┴───────────────────────────────────┘

      That is not "the" novel; it is an arbitrary one. Most other databases refuse the query outright. Treat a column that is neither grouped nor aggregated as a bug.

    Step 12: SQL from Python¶

    Programs use databases through code, not the shell. Python's built-in sqlite3 module runs SQL on a SQLite file. Save this next to books.db and run it:

    kadare.py
    import sqlite3
from contextlib import closing

with closing(sqlite3.connect("books.db")) as connection:
    cursor = connection.execute(
        "SELECT title, year FROM books WHERE author = ? ORDER BY year",
        ("Ismail Kadare",),
    )
    rows = cursor.fetchall()

print(rows[0])
for title, year in rows:
    print(year, title)

    ('Gjenerali i ushtrisë së vdekur', 1963)
1963 Gjenerali i ushtrisë së vdekur
1971 Kronikë në gur
1978 Prilli i thyer
    • sqlite3.connect() opens the database file.
    • connection.execute() runs one SQL statement and returns a cursor; fetchall() gives the rows as a list of tuples.
    • closing(...), from contextlib, closes the connection at the end of the block, like with open(...) closes a file.

    Changing data needs one more thing: a commit, which makes the change permanent. Using the connection itself in a with statement does it: it commits if the block succeeds, and rolls back if an exception is raised inside.

    add_book.py
    import sqlite3
from contextlib import closing


def add_book(path, title, author, year):
    """Insert one book and return its new id."""
    with closing(sqlite3.connect(path)) as connection, connection:
        cursor = connection.execute(
            "INSERT INTO books (title, author, year) VALUES (?, ?, ?)",
            (title, author, year),
        )
        return cursor.lastrowid


new_id = add_book("books.db", "Kështjella", "Ismail Kadare", 1970)
print("Added book", new_id)

    Added book 24

    On its own, with connection: commits but does not close the connection. That surprises almost everyone, hence closing as well. lastrowid is the id SQLite gave the new row.

    Placeholders, never f-strings¶

    Every query above has ? where a value goes, and passes the values separately, as a tuple. Never build SQL by pasting values into the string. See what happens when the "author" comes from a user who types x' OR '1'='1:

    injection.py
    import sqlite3
from contextlib import closing

name = "x' OR '1'='1"

with closing(sqlite3.connect("books.db")) as connection:
    query = f"SELECT title FROM books WHERE author = '{name}'"
    print(query)
    print(len(connection.execute(query).fetchall()), "rows")

    safe = connection.execute(
        "SELECT title FROM books WHERE author = ?", (name,)
    ).fetchall()
    print(len(safe), "rows")

    SELECT title FROM books WHERE author = 'x' OR '1'='1'
23 rows
0 rows

    The text closed the quote and added a condition that is always true, so the f-string query returned every row. With a placeholder, the same text is treated as a name, and matches nothing. This attack is called SQL injection, and it is still one of the most common ways real applications are broken into.

    AI in the loop

    Assistants write SQL fluently, and a confident query can still answer the wrong question. Before you run one, predict the result: how many rows, roughly what values. If the real result surprises you, find out why before you use it. And never run an UPDATE or DELETE from an assistant until you have run its WHERE as a SELECT and seen exactly which rows it touches.

    When something goes wrong¶

    The shell shows ...> and nothing happens

    The statement has no semicolon yet, so the shell is waiting for the rest. Type ; and press Enter.

    Parse error: no such table: books

    You opened a different database, often a new, empty one created by a typo in the file name. Check with .databases, and load books.sql into the file you meant.

    Parse error: no such column: Kadare

    Text needs single quotes: WHERE author = 'Ismail Kadare'. Without them, SQL reads the word as a column name. Double quotes are for the names of tables and columns, not for values.

    Parse error: misuse of aggregate

    An aggregate such as COUNT or SUM is in WHERE. Move the condition to HAVING, after GROUP BY.

    Runtime error: UNIQUE constraint failed or NOT NULL constraint failed

    The row breaks a rule of the table: a value that must be unique is already there, or a required column is missing. Read the column name in the message, and fix the data, not the rule.

    My query returns nothing, and I know the rows exist

    Check for = NULL (use IS NULL), for capital letters in text ('kadare' is not 'Kadare'), and for extra spaces inside the quotes.

    sqlite3.ProgrammingError: Cannot operate on a closed database.

    The code used the connection after the closing(...) block ended. Do all the work, including fetchall(), inside the block.

    8. From Python. Write a function titles_by(path, author) that returns a list of one author's titles, oldest first, using a placeholder.

    titles_by.py
    import sqlite3
from contextlib import closing


def titles_by(path, author):
    """Return the titles of one author's books, oldest first."""
    with closing(sqlite3.connect(path)) as connection:
        rows = connection.execute(
            "SELECT title FROM books WHERE author = ? ORDER BY year",
            (author,),
        ).fetchall()
    return [title for (title,) in rows]


print(titles_by("books.db", "Jane Austen"))
print(titles_by("books.db", "Nobody"))

    Quick reference¶

    SQL What it does
    CREATE TABLE t (id INTEGER PRIMARY KEY, ...) Create a table
    DROP TABLE IF EXISTS t Delete a table and its data
    SELECT col1, col2 FROM t Read some columns
    WHERE cond AND cond Keep matching rows
    ORDER BY col DESC LIMIT n OFFSET m Sort, then keep a page of rows
    INSERT INTO t (cols) VALUES (...), (...) Add rows
    UPDATE t SET col = value WHERE ... Change matching rows
    DELETE FROM t WHERE ... Remove matching rows
    COUNT(*), SUM, AVG, MIN, MAX Summarise rows
    GROUP BY col HAVING cond One row per group; filter the groups
    BEGIN; ... COMMIT; or ROLLBACK; Keep or undo a group of changes
    .headers on, .mode box, .tables, .schema t SQLite shell settings and inspection
    connection.execute(sql, (value,)) Run SQL from Python, with placeholders
